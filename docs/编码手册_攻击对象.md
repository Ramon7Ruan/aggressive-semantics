# 编码手册：攻击对象（v1）

用于双编码信度检验。编码对象是**单条发言**（微博评论，通常 10–30 字）。
标注界面：`data/annotation/annotate.html`（离线单文件，双击打开）。

本手册的取值与指标 `G2_target` 完全一致，这样人工编码与词表编码才能算 κ。

---

## 一、四个取值

| 取值 | 含义 | 典型表述 |
|---|---|---|
| `none` | 没有攻击。含纯陈述、纯情绪、纯立场表达 | 「希望能快点好起来」 |
| `opinion` | 攻击某个观点、说法、立场，不指向人 | 「这种逻辑站不住脚」「你这话没道理」 |
| `person` | 攻击特定个人。含第二人称「你」指代对方 | 「他在胡说」「你就是不懂」 |
| `group` | 攻击群体、机构、国家、地域、行业、性别、国籍 | 「韩国人都这样」「资本没一个好东西」 |

**判定顺序：先问「有没有攻击」，再问「攻击谁」；「攻击谁」按 group > person > opinion 取优先级。**
优先级理由是：越靠前越是「对人」，越靠后越是「对事」；顺序反了会把群体攻击记成观点分歧。

---

## 二、什么叫「攻击」

满足任一即算：

1. **侮辱/贬损词**：骂人的词、贬义标签（「脑残」「垃圾」「狗」）。
2. **褒词反用**：字面是褒义，语境是挖苦（「睿智」「典」「赢麻了」「急了」）。
3. **全称贬损**：用「都／一律／没一个」把负面属性推给整类人。
4. **人身否定**：不驳观点而否定人的能力、动机、智力（「你懂什么」「收了多少钱」）。

**不算攻击**（记 `none` 或按对象记 `opinion`）：

- 单纯反对：「我不同意」「这不合理」→ `opinion`
- 强情绪但无对象：「气死了」「太离谱了」→ `none`
- 自嘲、玩梗但无指向：「我太菜了」→ `none`
- 引用他人观点再反驳：攻击落在观点上 → `opinion`

## 三、边界情形（先定规则，遇到再查）

| 情形 | 判为 | 理由 |
|---|---|---|
| 「你们这些人」 | `group` | 「你们这些人」是类别化指称，非单个人 |
| 「你」（回帖对线） | `person` | 指向对话中的具体对方 |
| 「美国人」「韩国人」「外国人」 | `group` | 国籍/地域即群体 |
| 「某公司」「某平台」「资本」 | `group` | 机构/抽象集体按群体处理 |
| 「孙小果」「蓬佩奥」 | `person` | 可指名的具体个人 |
| 「这种政策」「这套制度」 | `opinion` | 对象是观点/做法，不是人 |
| 骂明星粉丝群体「饭圈」 | `group` | 群体 |
| 骂一句「傻逼」但无上下文 | `person` | 脏话默认指向对话对方；若整条在骂某群体则记 `group` |
| 反讽「真是大聪明」 | `person` | 反讽需有对象；指对方即个人 |
| 反讽但对象是政策 | `opinion` | 「这政策真是高招」→ 攻击做法 |

**一条里有多个对象时取最高优先级**（group > person > opinion），因为研究关心的是「是否升级到群体」。

---

## 四、拿不准怎么办

点「拿不准」（快捷键 5），不要硬猜。

- 标 `uncertain` 的条目**不计入 κ 的分母**，单独报比例。
- 若 `uncertain` 超过 15%，说明手册还不够用：先补规则，再重编，不要带着模糊标准算 κ。
- 不要在标注完成后回头改判据——那会让 κ 变成「与自己的一致性」。

---

## 五、κ 怎么判

| κ | 处理 |
|---|---|
| ≥ 0.70 | 该维度可用于假设检验（`config.MIN_KAPPA`） |
| 0.60–0.70 | 不算通过。找出分歧最多的类别，补规则后重编那部分 |
| < 0.60 | 手册重写：多半是类别边界没定义清楚，而不是编码者不认真 |

同时必须看**逐类 F1 与混淆矩阵**：κ 会被「多数类占绝对优势」抬高（kappa paradox），
所以不能只看一个数。样本已按阳性/阴性各半分层，就是为了压住这个问题。

## 六、本次编码的操作步骤

1. 双击 `data/annotation/annotate.html`（Chrome/Safari 均可，无需联网）。
2. 逐条按 1/2/3/4 选择；按 5 标「拿不准」；Backspace 回上一条。
3. 进度自动存在浏览器本地，关掉再打开会接着来。
4. 标完点「导出 CSV」，得到 `kappa_sheet_A.csv`（只有 `id,target` 两列）。
5. 把文件放到 `data/annotation/` 下，运行：

```bash
python scripts/kappa_report.py --a data/annotation/kappa_sheet_A.csv \
                               --b data/annotation/kappa_sheet_B.csv
```

（`_B.csv` 由第二名编码者独立完成，两人在编码期间不讨论具体条目。）

---

## 七、为什么这件事不能省

现在所有 T3/T5 的分类、以及「攻击对象是否为人/群体」的结论，都挂在**一个人的判断**上。
没有 κ，审稿人无法区分「这是数据的性质」与「这是编码者的习惯」。
这一步的成本是一小时，收益是把「印象」变成「测量」。
